# AI itinerary generation and view (S-03) Implementation Plan

## Overview

Implement roadmap slice **S-03** (`ai-itinerary-generation`): the validation-milestone slice. From a saved trip's detail page, a signed-in user triggers AI generation and sees a **day-by-day itinerary** — per-day activities, approximate per-day costs, and an approximate total (FR-009, FR-010, US-01). Generation **streams progressively** to the UI, **persists** to the existing `trips.itinerary_json` column on completion, enforces the **30-second NFR** with a safe abort + inline error, and is **one-shot** (no regenerate, per PRD Non-Goals).

## Current State Analysis

- **Schema:** `trips.itineraryJson` is a nullable `text` column — `src/db/schema.ts:66`. **No migration needed**; this slice writes to it for the first time.
- **Queries:** `src/lib/trips/queries.ts` has `getTripForUser(db, userId, tripId)` (ownership-scoped fetch) and `listTripsForUser` (now excludes `itinerary_json`). No update helper yet.
- **Trip detail:** `src/app/(protected)/trips/[tripId]/page.tsx` is an RSC shell that loads the trip via `getTripForUser`, `notFound()`s on missing/wrong-owner, and renders destination/duration/budget plus a static itinerary placeholder. This placeholder is what S-03 replaces.
- **API pattern:** route handlers use `auth()` → `getCloudflareContext({ async: true })` → `getDb()` → Drizzle, returning `NextResponse.json({ error })` on failure (e.g. `src/app/api/trips/[tripId]/route.ts`). `/api/trips/*` is guarded in-handler (not behind the `(protected)` layout).
- **No AI/validation deps:** `ai`, `@ai-sdk/*`, and `zod` are **not** installed. S-02 used hand-rolled validation; structured AI output is idiomatically Zod-schema driven via the AI SDK.
- **Secret:** `OPENAI_API_KEY` is a Worker secret (`infrastructure.md:167`); locally it must be in `.dev.vars`.

### Key Discoveries:

- **Streaming is mandatory, not optional.** The Cloudflare free-plan 10ms CPU ceiling silently 500s a buffer-then-parse approach — a documented 2-day production incident (`infrastructure.md:83`). The mandated mitigation is the **Vercel AI SDK `streamText`/`streamObject` with the OpenAI provider** (most Workers test coverage — `infrastructure.md:95,126`). Streaming I/O wait consumes ~zero CPU.
- **30s NFR sits exactly at the edge timeout with no buffer** (`tech-stack.md`). Abort the model call at ~28s to surface a clean error before the runtime hard-kills the request.
- **Cost disclaimer is fixed by PRD:** "All costs are estimates generated by AI. Actual prices may vary." (`prd.md:125`).
- **Budget is a planning signal, not a cap** (`prd.md:117,123`) — the prompt soft-targets it.
- **One-shot generation:** no "Regenerate" button (`prd.md:136`). Once `itinerary_json` is set, the detail page renders it read-only and the route refuses to overwrite.
- **AGENTS.md:** Next.js 16 has breaking changes — read the relevant guide in `node_modules/next/dist/docs/` before writing route-handler/streaming code; verify via the running app, not just typecheck.

## Desired End State

A signed-in user opens a saved trip with no itinerary, clicks **Generate itinerary**, and watches a day-by-day plan fill in live (activities + approximate EUR costs + total) with the estimates disclaimer. The itinerary is saved; reopening the trip shows it read-only with no Generate button. If generation exceeds ~28s or the API fails, an inline error with **Try again** appears and nothing is persisted. Cross-user or unauthenticated access to the generation route returns 404/401. Automated checks (`npx tsc --noEmit`, `npm run lint`, `npm run build`) pass.

## What We're NOT Doing

- **Regeneration / overwrite** of an existing itinerary (PRD Non-Goal) — S-03 is generate-once.
- **Activity editing / saving edits** — that is S-05 (`itinerary-activity-edit`, FR-011/FR-012).
- **Recalculating costs** after any later edit — original AI estimates are preserved (FR-010 resolution).
- **A test runner / unit tests** — verification matches S-02 (tsc/lint/build + runtime `/verify`). Testing infra is a separate concern.
- **Live/real pricing, maps, exports, hotels/flights, collaboration** (PRD Non-Goals).
- **A generation-status schema column / distributed lock** — duplicate generation is handled by client-disable + server idempotency on the null-check.
- **New trip fields** — EUR remains a display convention over existing integers.

## Implementation Approach

Add the AI SDK + Zod. Define one **Zod itinerary schema** (`days[] → activities[]` + `totalApproxCostEur`) that is the single source of truth for both the streaming-generation contract and the UI type. Build a **prompt** that feeds destination + duration + budget (soft-targeted) and asks for EUR estimates. Add a **streaming route handler** `POST /api/trips/[tripId]/itinerary` that authorizes, enforces ownership (404), refuses if an itinerary already exists (idempotency), calls `streamObject` (gpt-4o-mini) under an `AbortSignal.timeout(~28s)`, and **persists in `onFinish`** (D1 write is near-zero CPU). The client trip-detail component uses the AI SDK React `useObject` hook to call the route and **progressively render** the partial object; the Generate button shows only when `itinerary_json` is null and disables while streaming; errors render inline with Try again.

## Critical Implementation Details

- **Streaming protocol pairing:** the route returns `streamObject(...).toTextStreamResponse()` and the client consumes it with `experimental_useObject` (from `@ai-sdk/react`) bound to the same Zod schema. Both sides must reference the identical schema or partial parsing breaks. Confirm the exact export names against the installed AI SDK version's docs before wiring.
- **Persist post-stream, keep it lean:** do the D1 write inside `onFinish` using the SDK-assembled object; avoid heavy re-validation there (the stream already validated against the schema). The write targets the row only when `itinerary_json IS NULL` for that `(id, userId)`.
- **onFinish write must survive the response lifecycle (load-bearing):** on the workerd runtime, async work that runs after the response stream begins flushing can be torn down before it commits unless it is tied to the request lifecycle. Ensure the `onFinish` D1 write either completes within the stream pipeline or is registered via `ctx.waitUntil(...)` (Cloudflare execution context) so it is guaranteed to finish. Treat client-disconnect mid-stream (onFinish never fires → nothing persisted) as acceptable, not a bug. This is the exact "streaming behaves differently on Workers" risk in `infrastructure.md:95` — verify the write under real streaming (`preview:cf`), not just `next dev`.
- **Timeout margin:** abort at ~28000ms, not 30000ms, so the inline error renders before the edge runtime hard-kills the request.
- **Local secret:** generation needs `OPENAI_API_KEY` in `.dev.vars` for `npm run dev` / `preview:cf`; surface this in manual verification rather than assuming it is set.

## Phase 1: Foundation — deps, itinerary schema, prompt, persistence helper

### Overview

Install AI/validation dependencies and build the non-streaming units the route and UI both depend on: the Zod itinerary schema + type, the prompt builder, and a persistence query helper. No network or UI yet.

### Changes Required:

#### 1. Dependencies

**File**: `package.json`

**Intent**: Add the Vercel AI SDK, its OpenAI provider, the React hook package, and Zod for structured output.

**Contract**: Add runtime deps `ai`, `@ai-sdk/openai`, `@ai-sdk/react`, `zod`. Pin to versions compatible with React 19 / Next 16; verify install resolves cleanly. No other manifest changes.

#### 2. Itinerary schema + type

**File**: `src/lib/trips/itinerary.ts` (path illustrative)

**Intent**: Define the single Zod schema that is both the AI structured-output contract and the persisted/rendered shape, plus an inferred TS type.

**Contract**: Zod object — `{ days: Array<{ day: number; title: string; activities: Array<{ name: string; description: string; approxCostEur: number }> }>; totalApproxCostEur: number }`. Export the schema and `type Itinerary = z.infer<...>`. Per-day cost is derived in the UI (sum of activities), not a model field. Keep field names stable — they are the wire contract for streaming.

#### 3. Prompt builder

**File**: `src/lib/trips/itinerary.ts` (same module) or `src/lib/trips/prompt.ts`

**Intent**: Build the generation prompt from a trip's destination, duration, and budget, soft-targeting the budget and requesting EUR estimates.

**Contract**: Function `(input: { destination: string; durationDays: number; budgetAmount: number }) => string` (or system+user message parts). Instructs: plan `durationDays` days in `destination`, aim roughly within `budgetAmount` EUR **as a guideline, not a hard cap**, give 2–4 activities/day each with a short description and an approximate EUR cost. Output shape is enforced by the Zod schema, not restated in prose.

#### 4. Persistence helper

**File**: `src/lib/trips/queries.ts`

**Intent**: Add an ownership-scoped, idempotent update that writes a generated itinerary to `itinerary_json`.

**Contract**: `updateTripItinerary(db, userId, tripId, itinerary: Itinerary)` — serializes to JSON, updates the `trips` row matching `id = tripId AND userId = userId AND itinerary_json IS NULL`, bumps `updatedAt`. Returns whether a row was written (so the route can detect an already-generated race). Does not throw on no-op.

## Phase 2: Streaming generation route

### Overview

The risky edge/streaming surface, isolated for API-level verification before any UI. A streaming route that authorizes, enforces ownership and one-shot idempotency, generates with gpt-4o-mini under a 28s abort, and persists on finish.

### Changes Required:

#### 1. Generation route handler

**File**: `src/app/api/trips/[tripId]/itinerary/route.ts`

**Intent**: `POST` streams a generated itinerary for the caller's trip and persists it when the stream completes.

**Contract**: Reads `tripId` from params. `auth()` guard → 401 `{ error }` if no session. `getCloudflareContext({ async: true })` + `getDb()`. Fetch via `getTripForUser`; missing/wrong-owner → 404 `{ error }`. If `itinerary_json` already set → 409 (or 400) `{ error }` (idempotency; no overwrite). Otherwise call `streamObject({ model, schema, prompt, abortSignal: AbortSignal.timeout(28000) })` and return `.toTextStreamResponse()`. In `onFinish`, call `updateTripItinerary` with the assembled object (only persists on the still-null row). Follows the `register/route.ts` error-contract shape.

**Env / provider note**: The OpenAI key MUST be read from the Cloudflare env binding, not `process.env` — every secret in this repo is accessed via `getCloudflareContext().env` (`src/lib/db.ts:10`, `src/lib/auth.ts:12`), and `process.env` is used nowhere. The AI SDK's bare `openai(...)` default resolves the key from `process.env.OPENAI_API_KEY`, which is not reliably populated on the workerd runtime (and the gap is masked in `next dev`). Build the provider explicitly from the CF env, and add `OPENAI_API_KEY` to the worker env type (`cloudflare-env.d.ts` / `Env`).

**Contract note (snippet — env-from-CF + streaming pairing are both load-bearing and version-sensitive)**:
```ts
import { createOpenAI } from "@ai-sdk/openai";
const { env } = await getCloudflareContext({ async: true });
const openai = createOpenAI({ apiKey: env.OPENAI_API_KEY });

const result = streamObject({
  model: openai("gpt-4o-mini"),
  schema: itinerarySchema,
  prompt: buildItineraryPrompt(trip),
  abortSignal: AbortSignal.timeout(28_000),
  onFinish: async ({ object }) => {
    if (object) await updateTripItinerary(db, userId, tripId, object);
  },
});
return result.toTextStreamResponse();
```
Verify `createOpenAI` / `streamObject` / `toTextStreamResponse` / `onFinish` signatures against the installed `ai` / `@ai-sdk/openai` versions before finalizing.

## Performance Considerations

Streaming keeps Worker CPU near-zero during the model *call* (I/O wait is free) — the documented mitigation for the free-plan 10ms ceiling. Note, though, that `streamObject` runs full Zod validation of the assembled object on-Worker during finalization (before `onFinish`); that validation is the ~35ms CPU cost from the `infrastructure.md:83` incident and is inside the SDK regardless of how lean `onFinish` is. Keeping `onFinish` lean (skip re-validation, just the single D1 write) reduces the *incremental* cost, but the actual safeguard for the SDK's own validation cost is the **paid plan ($5/mo), the real production minimum for AI routes**. Per `infrastructure.md`, also test streaming under realistic concurrency before launch.
